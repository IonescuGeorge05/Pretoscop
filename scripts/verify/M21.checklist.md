M21 — founder check (about 30 minutes now; the rest follows the third parties)
1. Read infra/bot-program/README.md: what is built, the order of operations and the status table you will keep up to date.
2. Open http://localhost:3000/bot (make dev). Check the section "Cum verifici că o cerere vine de la noi" (IPs, reverse DNS crawl-N.bot.pretoscop.ro, Web Bot Auth status) and the table of anti-bot services. Everything it promises must match how the crawler behaves. It describes PretoscopBot only and sends readers to /metodologie for the other sources.
3. Web Bot Auth locally: run `pnpm --filter @pretoscop/fetch bot-auth:keygen`, put the printed WEB_BOT_AUTH_PRIVATE_KEY in your local .env (never commit it), restart, open http://localhost:3000/.well-known/http-message-signatures-directory (one JWK with kid and use) and run `pnpm --filter @pretoscop/worker bot:check --site http://localhost:3000 --skip-dns`: the directory line must be OK. Leave WEB_BOT_AUTH=false. Remove the key afterwards if you do not keep it.
4. Probe one blocked and one open shop from your connection (a live request, so only when you decide to): set CRAWL_ENABLED=true in your shell, switch on the flag `shops.probe.enabled` in http://localhost:3000/admin/flaguri, run `pnpm --filter @pretoscop/worker shops:probe evomag --vantage "founder home connection, honest UA"` and the same for dedeman (at most three requests each, 5 s apart), then switch the flag off. Compare with the probes in packages/config/shops/*.yaml; add `--write` when you want the result recorded, review the diff, commit it.
5. A4 (when the server exists): extra IPv4, PTR and A records as in infra/bot-program/reverse-dns.md; set BOT_EGRESS_IPS, add a changelog entry in apps/web/src/lib/bot-policy.ts, deploy, then `bot:check` must be all OK and `dig -x <ip>` must return crawl-1.bot.pretoscop.ro.
6. Production key: keygen on a trusted machine, key in the web and worker environments, deploy with WEB_BOT_AUTH=false, check the directory on https://pretoscop.ro (200, no redirect), register it, then WEB_BOT_AUTH=true (infra/bot-program/web-bot-auth.md).
7. C2: submit Cloudflare (Data Collection, Request Signature), Akamai, DataDome and Fastly with the dossiers in infra/bot-program/; keep the confirmation emails; update BOT_PROGRAMS and the status table.
8. C3: send the outreach emails from infra/bot-program/outreach-templates.md (feed-listing-v1 can go today; allowlist-v1 after steps 5–6) and log each in http://localhost:3000/admin/contactari (role addresses only; a Gmail/Yahoo address is refused) until it shows at least 8 shops contacted.
9. Canary: when crawling runs in production, switch on the flag `extractors.canary.enabled` (admin → Flaguri); the job runs on Mondays at 04:30 and alerts on Telegram when a shop's page layout or fields change, or when the canary itself is blocked.
