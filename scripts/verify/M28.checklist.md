M28 — 5-minute founder check (B2B price intelligence)
Everything customer-facing is off by default: `b2b.enabled` (workspaces and API for customers),
`b2b.digest.enabled` (daily email) and `b2b.billing.enabled` (Stripe subscriptions, also needs the
`STRIPE_*`/`B2B_STRIPE_*` lines of `.env`, setup D3). Admins can provision and open every
workspace while `b2b.enabled` is off. `make verify M=28` already ran every flow on this checkout's
database (Stripe only as signed test webhooks and a local mock).

1. Pilot workspace: /admin/b2b → "Spațiu de lucru nou": the merchant's name, type "magazin", the
   slug of its shop (as in /admin/surse or the M20 merchant page), plan Pilot, the owner's email.
   You land on its page; "deschide spațiul" opens it as admin (a yellow note says the terms are not
   accepted yet).
2. Owner's view: in a private window go to /b2b with the owner's address (magic link in Mailpit, or
   the real inbox). The workspace is listed; it opens on the data-usage terms; tick the box and
   accept ("Termenii au fost acceptați"). /pentru-companii/termeni is the full text (no resale, no
   publication, no AI training, no price coordination).
3. Import 50 SKUs: "Import SKU-uri" → paste 50 EANs of products the merchant sells (one per line,
   or a sheet with the columns `cod_intern;ean;mpn;marca;nume;pret`) → "Importă". The summary says
   how many were found in the catalogue, how many are not yet (retried every night), duplicates and
   bad lines (with their line numbers). "Alege din catalog" adds a product by name/MPN/GTIN.
4. Position table: "Poziții" shows per SKU the merchant's price (its live offer), the competitors'
   minimum (fresh, in-stock, new offers only), the cheapest shop, the median, the gap to the
   minimum, the rank and the last check; red rows are above the minimum. Click a product: every
   competitor offer (grey = not counted, with the reason), the observed history chart.
5. CSV: "Descarcă CSV" → opens in a spreadsheet with the same columns and values as the table
   (dot decimals, UTF-8); a SKU code like `=SUM(1)` shows as text, never as a formula.
6. API (Pilot and Pro): "API" → "Creează o cheie" → the key is shown once. Then
   `curl -H "Authorization: Bearer <key>" http://localhost:3000/api/v1/b2b/positions?limit=5`
   answers JSON (contract: /api/v1/b2b/openapi.json, also docs/api/b2b-v1.openapi.json); "Revocă"
   makes the same call answer 401. The daily quota (Pilot 2,000 requests) is on the same page.
7. Digest: turn on `b2b.digest.enabled` and run `pnpm --filter @pretoscop/worker b2b:digest` (the
   worker also runs it at 07:45): each member who kept "Rezumatul zilnic" on gets one email with
   the observed price and stock changes of the last 24 hours (Mailpit locally); nothing when nothing
   changed; a second run the same day sends nothing new.
8. Disclosure: /cum-castigam-bani "Analize de preț pentru firme" names the plans and the rules
   (no personal data, no Icecat content, internal use only, no effect on the ranking).
9. Billing (after D3): put `STRIPE_SECRET_KEY`, `B2B_STRIPE_WEBHOOK_SECRET` (endpoint
   https://<site>/api/webhooks/stripe-b2b, events checkout.session.completed,
   customer.subscription.created/updated/deleted, invoice.paid) and the two price ids in `.env`,
   turn on `b2b.billing.enabled`; a Starter/Pro workspace with its billing data filled in gets
   "Abonează-te" in Setări. Each paid period appears in /admin/b2b/facturi with the buyer's CUI and
   address for the accountant (CSV), where you record the e-Factura invoice number.
