M18 — 5-minute founder check (production deployment, backups, monitoring, staging)
Without a server or domain yet (A1, A4), steps 1–3 run locally; steps 4–6 need the accounts.
1. `make verify M=18` prints OK (about 30 minutes; Docker Desktop on Windows or macOS, or Linux).
   It rehearses production on this machine and removes everything afterwards: Caddy with TLS on
   https://localhost:8443, two web replicas, the worker, PostgreSQL with pgBackRest writing to a
   local S3 (MinIO standing in for R2), encrypted backups, a point-in-time restore after an
   accidental DELETE of the whole price history (every event comes back), a disaster recovery into
   an empty disk, the weekly restore test, a second deploy with 0 failed requests that leaves the
   database running, a rollback, a release refused for an invalid .env while the old one keeps
   serving, Plausible behind the proxy, a k6 load test, and an outage as the uptime monitor sees it. The alert rules are unit-tested too (they fire on each failure).
2. Read `infra/runbooks/server-setup.md` and `infra/runbooks/restore.md` (10 minutes): they are
   what you will do on the server; tell us what is unclear.
3. Put the backup passphrase rule in both password managers now (`PGBACKREST_REPO1_CIPHER_PASS`,
   `infra/runbooks/restore.md`): without it the physical backups cannot be restored.
4. With the server and Cloudflare: open https://staging.pretoscop.ro (Cloudflare Access login),
   then https://pretoscop.ro/api/health shows `"status":"ok"` and the release tag.
5. Better Stack: the six monitors of `infra/monitoring/README.md` are green; ask the agent to stop
   the web replicas for two minutes and confirm the alert reaches both phones.
6. Grafana Cloud (optional): the "Pretoscop — operations" dashboard shows the freshness panel green.
